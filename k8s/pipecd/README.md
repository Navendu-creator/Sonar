# PipeCD (production setup)

[PipeCD](https://pipecd.dev/) v0.58.0 in the `pipecd` namespace, built from the
official docs and Helm charts:

- [Installing Control Plane on Kubernetes](https://pipecd.dev/docs-v0.58.x/installation/install-control-plane/installing-controlplane-on-k8s/)
- [Control Plane configuration reference](https://pipecd.dev/docs-v0.58.x/user-guide/managing-controlplane/configuration-reference/)
- [Installing piped on Kubernetes](https://pipecd.dev/docs-v0.58.x/installation/install-piped/installing-on-kubernetes/)

PipeCD has two parts. The **control plane** is the web UI, API, projects and
deployment history. **piped** is the agent that watches git and deploys to the
cluster it runs in.

## Layout

Each service has its own folder and can be changed on its own:

```
k8s/pipecd/
├── kustomization.yaml          # kubectl apply -k k8s/pipecd → namespace + mysql + filestore
├── versions.env                # PIPECD_VERSION for control plane AND piped
├── namespace/                  # pipecd namespace (Pod Security "baseline")
├── secrets/
│   └── create.sh               # generates credentials → .secrets/ + Kubernetes Secrets
├── mysql/                      # datastore: MySQL 8.4 StatefulSet, 5Gi volume
│   ├── kustomization.yaml      #   image tag lives here
│   ├── statefulset.yaml
│   ├── service.yaml
│   └── network-policy.yaml     #   only control plane pods may connect
├── filestore/                  # filestore: SeaweedFS (S3 API) StatefulSet, 5Gi volume
│   ├── kustomization.yaml      #   image tag lives here
│   ├── statefulset.yaml
│   ├── service.yaml
│   └── network-policy.yaml
├── control-plane/              # Helm release "pipecd"
│   ├── install.sh              #   install/upgrade
│   ├── create-project.sh       #   create a project, print its admin login
│   ├── values.yaml             #   replicas, resources, ingress, cache image
│   ├── control-plane-config.yaml  # datastore, filestore, SSO
│   ├── pdb.yaml                #   PodDisruptionBudgets (applied by install.sh)
│   ├── network-policy.yaml     #   locks down the Redis cache
│   └── kustomization.yaml      #   the two extras above
├── piped/                      # Helm release "piped"
│   ├── install.sh
│   ├── values.yaml
│   └── piped-config.yaml       #   git repos piped watches
└── .secrets/                   # generated credentials, gitignored, NEVER commit
```

## Updating one service

| To change | Edit | Then run |
|---|---|---|
| MySQL settings or version | `mysql/*.yaml` (version: `newTag` in `mysql/kustomization.yaml`) | `kubectl apply -k k8s/pipecd/mysql` |
| Filestore settings or version | `filestore/*.yaml` (version: `newTag` in `filestore/kustomization.yaml`) | `kubectl apply -k k8s/pipecd/filestore` |
| Control plane replicas, resources, ingress | `control-plane/values.yaml` | `k8s/pipecd/control-plane/install.sh` |
| Datastore/filestore connection, SSO | `control-plane/control-plane-config.yaml` | `k8s/pipecd/control-plane/install.sh` |
| PipeCD version | `versions.env` | `control-plane/install.sh`, then `piped/install.sh` |
| piped repos or settings | `piped/piped-config.yaml`, `piped/values.yaml` | `k8s/pipecd/piped/install.sh <project> <piped-id> <key-file>` |
| Add a credential | `secrets/create.sh` | `k8s/pipecd/secrets/create.sh`, then restart what uses it |

`control-plane/install.sh` always restarts the server and ops pods, because the
chart doesn't restart them when only the config changes. A MySQL change restarts
the MySQL pod, so the control plane is briefly unavailable.

## What makes this production-style

The official quickstart (`quickstart.enabled: true`) runs MySQL and MinIO with no
volumes and a hard-coded root password, so a restart wipes all data. This setup
doesn't use it:

| Concern | This setup |
|---|---|
| Datastore | Separate MySQL 8.4 StatefulSet on a persistent volume, dedicated non-root DB user |
| Filestore | Separate S3-compatible store on a persistent volume |
| Secrets | Generated by `secrets/create.sh` into Kubernetes Secrets, never in git or Helm values |
| Availability | 2 server and 2 gateway replicas, PodDisruptionBudgets, probes on everything |
| Resources | Requests and limits on every container |
| Network | NetworkPolicies: only control plane pods reach MySQL, the filestore and Redis |
| Versions | Charts and images pinned (`versions.env`, `newTag` fields) |
| Logs | JSON logs for log collectors |

**About the filestore:** the official docs use MinIO, but MinIO no longer
publishes container images. PipeCD's `MINIO` filestore type works with any
S3-compatible endpoint, so SeaweedFS stands in for it.

**What's still different on a real production cluster:**

- Use **managed MySQL** (RDS or Cloud SQL) and an **S3 or GCS bucket**, and drop
  the `mysql/` and `filestore/` folders. Only `control-plane-config.yaml`
  changes: point `datastore.config.url` at the database, and use `filestore.type: S3`
  with `bucket` and `region`, ideally authenticated through IRSA (`roleARN`/`tokenFile`).
- Put the UI behind an **ingress with TLS**: in `control-plane/values.yaml` set
  `ingress.enabled: true` and `server.args.secureCookie: true`. In piped, set
  `args.insecure: false` and change `apiAddress` to `<host>:443`.
- Turn on **SSO** (`sharedSSOConfigs` in `control-plane-config.yaml`) and stop
  using the static admin login.
- Keep the credentials in a secret manager (Vault, AWS Secrets Manager) and sync
  them with External Secrets Operator instead of `secrets/create.sh`.

## First install

Needs `kubectl`, `helm` 3.8+ and `openssl`, and runs against the current
kubectl context. It needs about 1.5 GB of RAM.

```bash
cd k8s/pipecd
kubectl apply -k namespace                  # 1. namespace
./secrets/create.sh                         # 2. credentials (generated once, reused after)
kubectl apply -k mysql                      # 3. datastore
kubectl apply -k filestore                  # 4. filestore
kubectl -n pipecd rollout status statefulset/pipecd-mysql --timeout=10m
./control-plane/install.sh                  # 5. control plane
./control-plane/create-project.sh production   # 6. project; prints admin login ONCE
```

The login page is also saved to `.secrets/project-production.html`.

### Open the UI

```bash
kubectl -n pipecd port-forward svc/pipecd 8081:8080   # 8080 is taken by Argo CD
```

Open http://localhost:8081 and log in with project `production` and the static
admin username and password from step 6.

### Install piped

1. In the UI: **Settings → Piped → + Add**, name it (for example `kind-sonar`) and
   save. Copy the **piped ID** and **piped key**; the key is shown only once.
2. Save the key and install:

   ```bash
   printf '%s' '<piped-key>' > .secrets/piped-key && chmod 600 .secrets/piped-key
   ./piped/install.sh production <piped-id> .secrets/piped-key
   ```

3. Within a minute, the piped shows as **Online** under **Settings → Piped**.

piped watches this repository (`main`) over HTTPS. To deploy an app with
PipeCD, add an `app.pipecd.yaml` next to its manifests and register it under
**Applications → + Add**.

**Don't let Argo CD and PipeCD manage the same app.** SonarQube is managed by
Argo CD with `selfHeal`, so the two tools would keep reverting each other's
changes. Delete the Argo CD Application before moving an app to PipeCD.

## Backups

```bash
# Datastore
kubectl -n pipecd exec pipecd-mysql-0 -- sh -c \
  'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction pipecd' > pipecd-$(date +%F).sql
```

- Filestore: deployment logs and app state, in PVC `data-pipecd-filestore-0`.
- `.secrets/`: **without `encryption-key`, encrypted data in the database can't
  be read.** Keep a copy somewhere other than this machine.

## Day-to-day

| Task | Command |
|---|---|
| Status | `kubectl -n pipecd get pods,pvc` |
| Server logs | `kubectl -n pipecd logs deploy/pipecd-server -f` |
| piped logs | `kubectl -n pipecd logs deploy/piped -f` |
| Ops page (projects, reset admin password) | `kubectl -n pipecd port-forward svc/pipecd-ops 9082` → http://localhost:9082 |
| MySQL shell | `kubectl -n pipecd exec -it pipecd-mysql-0 -- sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" pipecd'` |

## Tear down

```bash
helm -n pipecd uninstall piped pipecd
kubectl delete -k k8s/pipecd      # deletes MySQL, filestore and the namespace
```

The PVCs go with the namespace, so **all PipeCD data is lost**. Delete
`.secrets/` only after that, because its credentials no longer match anything.
